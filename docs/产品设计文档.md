## 1. 产品定位

**一句话**：扫码（或粘贴红果短剧链接）拿到 `series_id`，高清**连续刷剧**。

- 平台：Android（Flutter）
- 形态：竖屏短视频/短剧播放器，偏「连续沉浸式刷剧」而非「点播列表」
- 用途：个人工具，仅供学习研究，不存储、不分发影视内容

---

## 2. 目标用户与核心场景

| 场景 | 描述 | 对应入口 |
|---|---|---|
| 从二维码进入 | 在外部看到红果短剧二维码 → 扫码 → 直接到选集页 | 主页「扫码看剧」 |
| 从分享链接进入 | 复制红果分享链接/sid → 粘贴打开 | 主页输入框 +「打开」 |
| 从历史续播 | 上次看到一半 → 一键回到那一集继续 | 主页「最近观看」/「全部」 |
| 连续刷剧 | 选集后一路自动连播、上下滑切集 | 播放页 |

## 3. 信息架构

```
主页 HomePage
 ├─ 扫码 ScanPage ──────────────┐
 ├─ 粘贴 sid/链接 ──────────────┤
 └─ 最近观看/历史 HistoryPage ──┤
                                ▼
                    详情页 DetailPage（选集）
                      ├─ 封面 / 简介 / 季切换
                      ├─ 分集列表（高亮当前集）
                      └─ 选集 → 播放页 PlayerPage
                                │
                                ├─ 上下滑切集 / 自动连播
                                ├─ 全屏（横屏）
                                └─ 返回 → 详情页（高亮当前集）
```

设置页 `SettingsPage` 从主页右上角进入。

## 4. 页面规格

### 4.1 主页（HomePage）

- 顶部标题「短剧果果」；标题右侧**退出按钮**（电源图标，退出 App），右上角**设置**按钮。
- 「扫码看剧」主按钮 → 扫码页。
- sid / 分享链接输入框 +「打开」→ 解析 → 详情页。
- 「最近观看」列表：封面、剧名、看到第几集；点「全部」进历史页。

### 4.2 扫码页（ScanPage）

- 相机扫码，识别二维码中的 `series_id`（兼容短链重定向、PUGV 识别）。
- 识别成功 → 回传 sid → 进详情页。

### 4.3 详情页（DetailPage）

- 展示：封面、剧名、简介、完结/连载状态。
- **分集列表**：显示全部集数，**高亮当前播放的一集**，点集直接播放。
- **季切换**：若该剧属于多季系列，可切换季（`series_store` 映射表）。
- 支持「历史直达自动播放」：从历史进入时，加载完成后自动进入上次那集。

### 4.4 播放页（PlayerPage）

- 全屏视频，竖屏竖短剧、横屏全屏。
- **顶部左上**：返回按钮 + 「`第X/共Y集 剧名`」信息（普通/全屏都显示）。
- **底部一行**：进度条（含缓冲进度）+ 当前时长/总时长 + 全屏按钮。
- **中间**：暂停时显示播放图标（点击任意处切换播放/暂停）。
- 支持：上下滑切集、拖进度条 seek、缓冲中显示 spinner。

### 4.5 历史页（HistoryPage）

- 全部观看历史：封面、剧名、看到第几集、时间。
- 支持清除历史。

### 4.6 设置页（SettingsPage）

- **清晰度**：720p / 1080p 二选一（默认 **1080p**，1080p 失败自动回退 720p）。
- **禁止在移动网络下预取下一集**：默认关（移动网络也预取）；开启后仅 WiFi 预取。

## 5. 核心播放体验（本产品的灵魂）

围绕「**秒起播 · 无跳帧 · 秒切**」三条硬指标设计：

| 指标 | 含义 | 实现手段 |
|---|---|---|
| **秒起播** | 点开/切集后尽快出画面，不等整集下完 | 本地 HTTP 流式：边下边解密边喂播放器 |
| **无跳帧** | 播放过程中/切集瞬间不卡顿、不黑屏跳变 | 单条连续字节流，取消「部分文件→完整文件」的二次切换 |
| **秒切** | 切到下一集零 loading | 双播放器 + 预加载队列（后台预初始化后续集 controller） |

### 5.1 秒起播：本地 HTTP 流式（生产者/消费者）

应用内起一个 `HttpServer`（127.0.0.1 随机端口），播放器读
`http://127.0.0.1:port/play/{sid}/{vid}/{quality}`。

服务器扮演「生产者」：从红果 CDN **边下载加密流、边按样本解密、边写给 ExoPlayer**；
ExoPlayer 扮演「消费者」。moov 先到即先起播，mdat 渐进流式，**首帧无需等完整文件**。

- 1080p：单文件 HEVC（`hvc1`），stbl CENC，8 字节 IV。
- 720p：fMP4 双文件（video+audio 分离），on-the-fly mux 成单条 MP4，16 字节 IV + subsample。
- seek 支持 HTTP Range（只下所需密文区间，不整文件重下）。

### 5.2 无跳帧：一条字节流替代「head→完整版切换」

早期方案是「先播部分预取的 head 文件，再切到完整版文件」，切点有 PTS 断档 / surface
重建，必然跳帧。流式方案让播放器**从头到尾只面对一条连续流**，从架构上消除跳帧。

### 5.3 秒切：双播放器 + 预加载队列

切集不再「销毁当前 controller → 重新 `initialize` 下一集」（`initialize` 是切集卡顿
主因）。改为：

- 当前集播放时，后台**预初始化后续 N 集**的 controller 放进队列；
- 切集时直接从队列取出、`play()`，零 loading；
- 切走一集自动补一集，滑出窗口的旧 controller 释放。

> 预加载集数 N 受「红果 web 频道限流」约束，当前取较小值（见 §6 与 §10）。

### 5.4 缓存进度可视化

进度条上叠加**缓冲进度**（已缓冲时长/总时长），用同一滑杆的次级轨道色呈现，
让用户感知「缓存到哪了、seek 是否会卡」。

## 6. 清晰度策略

| 清晰度 | 通道 | 编码 | 说明 |
|---|---|---|---|
| 1080p（默认） | App `multi_video_model/v1` → fplay | HEVC `hvc1` 单文件 | 高清、流式 |
| 720p | web `play-info` | H.264（legacy 明文 或 CENC fMP4） | 兼容性最好 |

- 默认 **1080p**；1080p 播放失败自动回退 720p 并提示。
- 1080p 为 App 通道，720p 为 web 通道——因为 App 流的 360/480/540/720 是私有 `bvc2`
  编码无法解码，只有 1080p 是标准 HEVC；720p 必须走 web 通道的标准 H.264。

## 7. 关键交互细节

| 交互 | 行为 |
|---|---|
| 上下滑 | 切上下集（拖动跟手，超过阈值或速度够即切集） |
| 点击屏幕 | 播放/暂停切换（播放图标区域也穿透，不拦截点击） |
| 拖进度条 | 拖动过程只预览，**松手才 seek**（避免连续 seek 卡死） |
| 全屏 | 旋转 + 沉浸式，底部控件避让导航栏 |
| 返回 | 播放页左上角返回详情页，并高亮当前集 + 滚动到可见 |
| 退出 | 主页标题右侧电源按钮退出 App |
| 屏幕常亮 | 播放中保持常亮，暂停/退出关闭 |

## 8. 数据与持久化

| 数据 | 存储 | 说明 |
|---|---|---|
| 观看历史 | `shared_preferences` + 内存缓存 | 记录 series_id、剧名、封面、集数、进度（毫秒）、时间 |
| 清晰度设置 | `shared_preferences` | 默认 1080p |
| 移动网络预取开关 | `shared_preferences` | 默认关 |
| 系列剧（季）映射 | 本地映射表 `series_store` | 详情页季切换用 |

## 9. 设计原则与取舍

1. **播放体验优先**：宁可用本地流式 + 双播放器这套「重」架构，也要保证秒起播/无跳帧/秒切。
2. **清晰度默认 1080p**：App 通道高清且是标准编码，作为默认；720p 作为回退与兼容选项。
3. **限流敏感**：红果 web 通道会随机 403 限流，因此预加载集数、请求间隔、重试次数都
   做了收敛（见 §5.3），在「切集更跟手」与「少触发限流」之间取平衡。
4. **低成本交互**：封面过渡、首帧缩略图等「高成本低收益」的视觉暂不做（详见
   [`播放器设计分析.md`](播放器设计分析.md)）。
5. **工具化克制**：不引入登录、不接广告、不做社交，聚焦「扫码→刷剧」一条主链路。

---

## 10. 遗留与展望

- **LRU 缓存限额**：当前无磁盘缓存限额（历史留盘 + 预加载队列在内存），后续可加。
- **预加载集数自适应**：当前固定小值，可据限流观测动态调。
- **720p 完全按时间交错 mux**：当前「音频前置」已解决首帧等待，进一步可做音视频按
  PTS 完全交错，追求更极致的起播速度。
- **限流缓解**：play-info 内存缓存已做；可再上「全局串行 play-info 队列」进一步降限流。
